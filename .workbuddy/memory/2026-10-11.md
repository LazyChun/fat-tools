## 排查「加载插件后啥都没有」

排查方法与结论（重要，后续复用）：
- 运行中应用：UI 服务 http://127.0.0.1:8888，后端 API http://127.0.0.1:8022（端口从 index.html 注入的 `window.__FAT_SERVER_PORT__` 读取）。
- 直接查后端即可判断加载态：`GET /app/bespokePlugin/listActiveBespokePlugins`（注意是 GET，POST 返回 405）。
- dev 插件静态路由：`/extensions/bespokePluginsDev/<pluginId>/__fat_dev_<mtime>/remoteEntry.js`，映射到 devPath（插件工程 dist），与 `bespokePlugins.json` 里 devMode/devPath 同步。
- 应用数据根目录是 D:/works/fBooks（不是 fat-notes-core/extensions），插件注册项在那里。
- **真正根因**：宿主 `registerPrimarySidebar(render)` 注册的视图 id 固定为 `${pluginId}.primarySidebar`；活动栏项若写自定义 `primarySidebarViewId`（如 "fat-tools.view"）则 `getPrimarySidebarView()` 查不到 → `useAppLayout.activeBespokeHasPrimarySidebar=false` → 宿主**主动隐藏整个主侧边栏**，表现为点击图标后空白。
- 修复：`primarySidebarViewId: \`${sdk.pluginId}.primarySidebar\``（或干脆省略，走 pluginId 兜底）；并新增 `safeRegister()` 逐项 try/catch，避免某个 SDK 方法缺失导致 activate 中断使全部 UI 消失。

## 修 toolSwitcher 切换栏「文字不居中」（用户反馈截图）

- 现象与定位：用户截图反馈 tab 文本不居中，怀疑没用 antd Segmented。实际源码本来就是 `<Segmented block size="small">`。
- 分析方法（很值得复用）：截图用纯 stdlib Python 解码 PNG（zlib+struct 解 IHDR/IDAT、逐行反 filter）逐像素测量。结论：
  - 水平方向其实是**完全居中**的：9 个 tab 等宽 159px，文字簇中心 109/267/426.5/… 与格心 109/268/427/… 一一吻合（误差 ≤1px）。
  - 垂直方向**文字偏高 ~2.5px**：track y 34..62（item 36..60，中心 48），文字 ink 40..51（中心 45.5）。
  - 对照组：同卡片下方 CalculatorTool 的 `<Radio.Group optionType="button">` 按钮盒 y160..183、文字 ink 165..177，**正中**。
- 根因：label 外面套了 `<span style={{display:"inline-block",overflow:"hidden",textOverflow:"ellipsis",whiteSpace:"nowrap",maxWidth:96}}>`。按 CSS 2.1 §10.8.1，**overflow 非 visible 的 inline-block 以底边为基线**，导致父级行盒多出 strut descent（≈4~5px），label div 从 L 变成 L+descent，行盒贴在 div 顶部 → 文字整体上移 ≈ descent/2。
- 修法：label 直接传字符串（`label: t.title`），空格与省略号交给 antd 自带的 `.ant-segmented-item-label`（已有 nowrap+ellipsis+padding）；`title` 会落到该 div 的原生 title 上（悬停看全名）。antd 6 的 Segmented option 还支持 `tooltip`（会包 Tooltip），`title` 不再是 tooltip。
- 环境备忘：antd 版本是 **6.3.1**（不是 5），Segmented 由 @rc-component/segmented 渲染；卡片内不吃 ThemeShell 的 ConfigProvider（ThemeShell 只包 MenuView/WorkPageView），所以卡片里字号是宿主默认。

## 修 toolSwitcher 卡片「在工具箱中打开」点击无效（用户反馈截图）

- 根因：宿主 `sdk.router` 是**纯内存路由**（fat-notes-core `pluginSdk/registry.ts` 的 `routerNavigate`：只改内部历史栈 + notify 订阅者），**不会切换宿主活动栏激活项**。工具箱页内部跳转有效是因为 WorkbenchPage 已挂载并订阅 onChange；仪表盘页面上工作台页未挂载 → 路由变了界面毫无反应。
- 宿主切换活动项的真实机制：ActivityBar `PluginItem.handleClick → dispatch(onActiveMenu("bespoke:<活动栏项id>"))`，action type 为 `frame/onActiveMenu`（frameSlice name:"frame"），payload 即 `frame.activityMenuKey`；Workbench 用 `bespoke:<id>` 匹配 workbenchPage.id 渲染右侧。
- 修法（ToolSwitcherBlock.tsx）：点击「在工具箱中打开」时 ① 先 `useDispatch()`（宿主与插件共享 react-redux 单例，同 DisplayConfig 面板模式）dispatch `{type:"frame/onActiveMenu", payload:"bespoke:fat-tools.main"}` 切活动栏（try/catch 兜底非宿主环境）；② 再 `sdk.router.navigate(path)`；③ `setPreferredToolId(active.id)` 与 openTool 命令行为一致。
- TS 坑：react-redux 9 `useDispatch<T extends Dispatch<UnknownAction>>`，泛型必须是函数类型（`(action:{type:string;payload?:unknown})=>unknown`），传对象类型报 "no call signatures"。
- typecheck / vitest 20 / webpack build 均通过；dev 模式宿主直接取工程 dist，刷新宿主页面即生效。
